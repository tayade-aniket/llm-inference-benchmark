The 60-Second Recruiter Summary

Modern machine learning usually takes gigabytes of VRAM for granted. This project demonstrates foundational systems literacy by deploying a state-of-the-art open-weights model onto a severely constrained dual-core CPU with only 4 GB total system RAM.

1. Memory-Bandwidth Bound Autoregressive decoding is mathematically bound by memory bus speed (16 GB/s DDR3). 4-bit quantization accelerates decoding by halving bus traffic per token.
2. Prefill is Compute-Bound Prompt prefill processes tokens concurrently in matrix-matrix multiplication (GEMM), operating at peak ALU compute rather than memory bandwidth.
3. Strict Memory Guardrails By capping context length and using native AVX2 SIMD memory-mapped files, active footprint stays at 337 MB RSS, avoiding catastrophic OS swap thrashing.

Roofline Performance Model

Mathematical derivation proving why autoregressive decoding is strictly memory-bandwidth bound.

Attainable GFLOPs/s vs Arithmetic Intensity (FLOPs/Byte)

Theoretical Derivations

Batch-1 Decoding Intensity:
$$\text{Intensity} = \frac{2 \text{ FLOPs/param}}{b / 8 \text{ Bytes}} = \frac{16}{b}$$
For Q4_K_M ($b=4.5$): 3.56 FLOPs/Byte
For FP16 ($b=16$): 1.00 FLOP/Byte
Hardware Roofline Knee:
$$\text{Knee} = \frac{\text{Peak Compute}}{\text{Memory Bandwidth}} = \frac{64 \text{ GFLOPs/s}}{16 \text{ GB/s}} = 4.0$$

Because $3.56 < 4.0$, **batch-1 token generation operates on the memory-bandwidth slope**. Every byte saved via 4-bit quantization translates directly into increased decoding speed!

Interview Talking Points & Deep-Dive FAQ

Technical insights designed for discussions with Engineering Hiring Managers.

Q1: Why does 4-bit quantization speed up CPU inference if CPU ALU is FP32?

CPUs do not compute directly in INT4; they unpack weights into SIMD registers. The speedup occurs because **decoding is memory-bandwidth bound**. For every token generated, all active weights must stream from RAM across the memory bus. 4-bit compression cuts bus traffic from 0.98 GB/token to 0.39 GB/token, reducing the time the CPU spends idling for memory lines.

Q2: What is the architectural difference between TTFT and ITL?

TTFT (Time to First Token) covers the prefill phase, which processes the full prompt matrix in a single batch (GEMM). This achieves high arithmetic intensity and is compute-bound. ITL (Inter-Token Latency) covers the autoregressive decoding phase, generating one token at a time via matrix-vector multiplication (GEMV), which is strictly memory-bandwidth bound.

Q3: Why can't vLLM run on this edge machine?

vLLM's PagedAttention kernels are written in CUDA C++ for NVIDIA GPUs with warp-synchronous scheduling and unified VRAM paging. They are designed for high-concurrency multi-user batching ($B \ge 16$). On edge CPUs with single-stream inference ($B=1$), `llama.cpp`'s native AVX2 SIMD with memory-mapped weights (`mmap`) delivers superior latency and consumes only 337 MB RAM.
